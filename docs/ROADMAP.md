# 路线图与规划

## 一、客服网页问答（widget）—— 当前状态与规划

**v1 已落地（本仓库）：**

- 商家端一键生成网页客服凭据（`店员管理 → 网页客服`）
- 公开配置/聊天接口（免登录、IP+凭据双限流、visitorId 续接会话）
- 自带最小可用问答页 `{服务器}/kefu/widget/<token>`，可直接发链接，也可 `<iframe src="...">` 嵌入店铺网页

**v2 规划（按优先级）：**

1. **可嵌入 SDK**：一段 `<script>` 悬浮球组件（右下角气泡），商家复制三行代码即可接入，
   支持自定义主题色、位置、商家 Logo；不再依赖整页 iframe。
2. **知识库 RAG**：商家在控制台上传商品资料 / 售后政策 / 常见问题（支持文档、表格、网页抓取），
   构建商家私有向量库；Agent 回复前先检索（工具或前置上下文注入）。
   可复用生态插件：`dsh-plugin-rag` / `dsh-library`（SQLite + 本地嵌入，零模型下载）做底座。
3. **转人工**：顾客侧「转人工」→ 商家店员在控制台实时接管（会话状态流转 user → staff，
   widget 端与店员端同会话实时同步，可用 SSE/WebSocket）。
4. **订单查询**：对接店铺订单 API 的插件化工具（商家配置只读凭证），Agent 可查订单状态/物流。
5. **多语言 / 多店铺**：一个商家多个 widget 皮肤；widget 页面 i18n。

## 二、平台能力规划

| 能力 | 状态 | 说明 |
|---|---|---|
| 账号 / 商家 / 角色 / 隔离 | ✅ v1 | scrypt + Cookie 会话，15 分钟失败锁定 |
| 店员 Agent（人设 / 档位 / 多轮） | ✅ v1 | 复用 DSH 会话引擎，SSE 流式 |
| 限流（账号 / IP / 凭据） | ✅ v1 | 内存滑动窗口，管理端可调 |
| 管理端（商家 / 账号 / 档位 / 审计） | ✅ v1 | 超管专属 |
| 网页问答 | 🟡 v1 基础版 | 见上 |
| 知识库 RAG | ⏳ 规划 | 见上 v2-2 |
| 用量计费（token / 消息 / 档位） | ⏳ 规划 | 已有 usage 采集（meta.usage），可做账单与限额 |
| 邀请码开号 / 手机号绑定 | ⏳ 规划 | 防滥用 |
| 操作审计增强 / 导出 | ⏳ 规划 | audit_log 已有基础 |
| 多服务器横向扩展 | ⏳ 远期 | 当前单机 SQLite；远期可换 Postgres + 共享会话存储 |

## 三、技术债 / 注意

- `dsh-kefu` 直接依赖 DSH 内部服务（`ctx.agents`、`webServer`、`systemPrompt`），
  版本升级（rc.x）时先跑一遍 E2E 冒烟（见 README「开发与测试」）。
- 客服 Agent 每轮 create/resume + dispose，会话热切换有约 0.1~0.5s 重建开销；
  高并发场景可做「常驻 Agent 池」优化（保留活跃会话的 agent 句柄，按会话复用）。
- 同会话并发消息已用进程内锁串行化（409 TURN_IN_PROGRESS）；多实例部署需换分布式锁。
