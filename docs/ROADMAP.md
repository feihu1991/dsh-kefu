# 路线图与规划

## 一、客服网页问答（widget）—— 当前状态与规划

**已落地（本仓库）：**

- 商家端一键生成网页客服凭据（`店员管理 → 网页客服`），提供三种接入方式：
  独立问答页 / **悬浮球 SDK**（`kefu-sdk.js`，一行 `<script>` 嵌入，可换主题色）/ 公开 API
- 公开配置/聊天接口（免登录、IP+凭据双限流、visitorId 续接会话）
- **知识库 RAG v1**：商家在控制台录入资料（可按 Agent 或全店共享），
  FTS5 trigram 整句匹配 + 2 字关键词 LIKE 回退的混合检索，命中资料作为权威依据注入 system prompt

**下一步规划（按优先级）：**

1. **知识库升级：向量化语义检索**：引入本地嵌入（可复用生态 `dsh-plugin-rag` / `dsh-library` 底座），
   解决口语问法与资料用词不一致时的召回问题；支持文档批量导入（复制粘贴、文件上传）。
2. **转人工**：顾客侧「转人工」→ 商家店员在控制台实时接管（会话状态流转，widget 端与店员端同会话实时同步）。
3. **订单查询**：对接店铺订单 API 的插件化工具（商家配置只读凭证），Agent 可查订单状态/物流。
4. **多语言 / 多店铺**：一个商家多个 widget 皮肤；widget 页面 i18n。
5. **知识库命中反馈**：统计每条资料被引用次数与顾客满意度，帮商家优化资料。

## 三、技术债 / 注意

- `dsh-kefu` 直接依赖 DSH 内部服务（`ctx.agents`、`webServer`、`systemPrompt`），
  版本升级（rc.x）时先跑一遍 E2E 冒烟（见 README「开发与测试」）。
- 客服 Agent 每轮 create/resume + dispose，会话热切换有约 0.1~0.5s 重建开销；
  高并发场景可做「常驻 Agent 池」优化（保留活跃会话的 agent 句柄，按会话复用）。
- 同会话并发消息已用进程内锁串行化（409 TURN_IN_PROGRESS）；多实例部署需换分布式锁。
